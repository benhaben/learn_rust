# 主人 / 外号 / move / 闭包

对应：`01_ownership`、`09_fn_traits`。

## 主人与外号

**主人**对这份数据负责到底：离开作用域就 `Drop`。  
**外号**（`&` / `&mut`）只是临时看着，不释放，不能活得比主人久。

| | 主人 `s: String` | 外号 `r: &String` |
|---|---|---|
| 所有权 | 有 | 没有 |
| 离开作用域 | `Drop`，堆被 free | 什么都不释放 |
| 能不能把数据搬走 | 能 | 不能 |
| 能活多久 | 自己说了算 | 必须 ≤ 主人 |
| 同时几个 | 只能一个 | `&` 可以很多；`&mut` 只能一个 |

`&` 不换主人，只是多一个只读外号。有 `&` 活着时，主人不能被 move，也不能再 `&mut`。  
`&mut` 也不是换主人，是唯一可写外号。

口条：**move = 换主人；`&` = 只读外号；`&mut` = 独占可写外号。**

## 第一任不是终身制

造出来时绑第一任主人（`String::from`、`let s = ...`）。`move` 之后第一任名字作废，新绑定才是主人。谁当主人谁 `Drop`。

`Rc::clone` 是多个主人一起数；最后一个没了才释放。

`take(String::from("x"))` 里的 `take` 只是举例用的普通函数，不是关键字。那个 `String` 的主人是参数 `s`，`take` 结束就 `Drop`。标准库另有 `std::mem::take`，不是一回事。

## move 不是「mut + 原来的作用域 Drop」

move = 所有权换主人，**值还在**，旧名字作废。旧处**不**跑 `Drop`（否则和新主人 double-free）。析构等新主人离开作用域。

`mut` 只是这个绑定能不能改，和搬不搬走无关。不 `mut` 也能 move。

## 为什么要有 `move` 关键字

闭包默认**能借就借**，好让闭包用完外面还能用。

闭包要活过当前栈（`spawn`、`return` 一个闭包）时，再借就会悬空，必须整份带走，所以写 `move`。

`move` 和 `Fn` / `FnMut` / `FnOnce` 是两轴：捕获方式 vs 调用能力。`move || println!("{n}")` 里 `i32` 是 Copy，仍可以是 `Fn`。`drop(s)` 不写 `move` 也会搬走 `s`。

## FnOnce / FnMut / Fn

日常写闭包**不用标**这三种。编译器按捕获自动 impl。

要写，是在**收闭包的 API** 上：

| 约束 | 含义 | 例子 |
|---|---|---|
| `FnOnce` | 可调一次，能吃掉捕获 | `spawn` |
| `FnMut` | 可多次，能改捕获 | `map`、`sort_by` |
| `Fn` | 可多次，不改捕获 | `\|x\| x + 1` |

`Fn: FnMut: FnOnce`。`fn call<F: Fn()>(f: F)` 是参数，不是把函数存下来。要存才是 `Box<dyn Fn()>`。

`thread::spawn` 要 `FnOnce + Send + 'static`。用到局部变量时几乎总是 `move ||`：默认借不是 `'static`。同线程里还要继续用 `n` 的 `|| n += 1` **不能** `move`，这种也 **不能** spawn。

口条：**闭包本身不标类型；标三种是「我吃什么样的闭包」。`FnMut` 是调用约定，`move` 是捕获约定。**
