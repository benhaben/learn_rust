# unsafe 边界

对应：`cargo run --bin 20_unsafe`。

## `unsafe` 做什么、不做什么

**不关闭**借用检查。只是多允许五件危险操作：

1. 解引用裸指针（`*p`）
2. 调用 `unsafe fn`
3. 读写可变静态变量
4. 实现 `unsafe trait`
5. 访问 union 字段

从引用做出指针（`&n as *const i32`）是安全的；**解引用**才要 `unsafe`。

裸指针别名 + 同时可变 = UB，不是看运气。

## 纪律

1. `unsafe` 块尽量小。
2. 不变量写在 `/// Safety:`：调用方必须保证什么。
3. 对外只暴露安全 API，调用方无法打破不变量。

## `safe_head` 和 `read_raw` 没有调用关系

两条线并排演示，不是一条链。

- `safe_head`：对照物。吃 `&[u8]`，返回 `Option`，调用方不用 `unsafe`。
- `read_raw`：吃裸指针，安全全靠约定，调错是 UB。

想说的是：能让人走切片这种接口，就别把裸指针交给业务。  
若接在一起，应把 `read_raw` **藏在** `safe_head` 里面；本文件用 `first().copied()`，不再走一遍裸指针。

## 为什么「自己写 Vec」要用 unsafe

你的感觉对了一半：**业务里不碰裸内存，就不用写 `unsafe`。** 用现成的 `Vec` / `String` / `&[T]` 即可。

「自己写 Vec」难的是：Vec **本身就是**一块堆内存 + 指针 + 长度 + 容量。安全 Rust 不允许你做这些事：

| Vec 要做的事 | 安全 Rust 为什么不够 |
|---|---|
| `cap > len`：后面是未初始化的坑 | 不能有「分配了但还不是合法 T」的值 |
| `push` 满了要 `realloc`，把旧元素挪到新缓冲 | 要按字节搬、解引用新指针 |
| `ptr` / `len` / `cap` 自己维护 | 编译器不管这三元组一不一致 |
| 按索引读写已初始化的那段 | 最终要对裸指针 `add` + 读/写 |

标准库的 `Vec` 内部全是 `unsafe`，外面给你的 `push` / `v[i]` 是安全封装——和「小 unsafe + 对外安全 API」是同一套。面试说「自己写 Vec」= 你要复刻这块**内存分配器式的不变量**，不是说写业务列表要用 unsafe。

无锁队列、FFI、SIMD 同理：要自己保证指针/对齐/别名，才需要 `unsafe`。

口条：**不操作内存就用不到 unsafe。自己写 Vec 就是在操作内存：未初始化容量 + 裸指针。对外仍只给安全 API。**
