# FPGA 在量化里干什么（没板子也能面）

对应口条总表：[`quant-sys-interview.md`](quant-sys-interview.md)。延迟数字见 `python3 10_latency_budget.py`。

## 买的是什么

CPU 是「很快但不稳」：cache miss、中断、系统调用、分支预测，p50 漂亮、p99 炸掉。  
FPGA 是**时钟节拍上的流水线**：同一份解析逻辑，每拍做什么是固定的，尾延迟接近平均。

所以 FPGA 不是「更强的 CPU」，是把**固定、宽、浅**的逻辑搬到线速硬件上。行情解码、增量簿记、阈值触发、硬风控、订单组包——这些字段位置和规则几个月才改一次，适合下板。每周改的因子、树、组合优化，留在 CPU / GPU。

## 典型切分（面试默画）

```text
光纤/交换机 ──► FPGA
                 ├ 协议解析（二进制、定长/TLV）
                 ├ 订单簿（价位数组，不是红黑树）
                 ├ 简单触发（价差、队列、取消率）
                 ├ 硬风控（最大下单、自成交、品种白名单）
                 └ 订单编码 ──► 柜台/交易所
                        │
                        │ PCIe DMA / 寄存器（已经是 200ns+ 一跳）
                        ▼
                      CPU 策略 / 中频 / 研究
```

两条产品形态：

| 形态 | 谁决策 | 延迟 | 谁在用 |
|---|---|---|---|
| 板卡做市 / tick-to-trade | 触发在 FPGA | 数百 ns–1 μs | 期货、期权做市 |
| 板卡当超级 NIC | FPGA 只解析+DMA，策略在 CPU | 1–5 μs | 更常见；好迭代 |

华钧官网写「FPGA 行情/下单 + 硬件机器学习」。面试默认按**第一条是目标、第二条是现状**来问：ML 下板极贵，往往只是很小的线性/树，或还在 CPU/GPU。追问「哪些信号真在板上」，比复读 slogan 强。

## 和内核旁路怎么选

| 手段 | 去掉哪一跳 | 策略还能怎么写 |
|---|---|---|
| 内核 TCP | 无 | 随便写 |
| Onload / DPDK | 内核拷贝、中断、协议栈 | 仍是 C++ 策略 |
| FPGA 解析 + CPU 策略 | 软件解析、部分拷贝 | C++ 仍在环上 |
| FPGA tick-to-trade | CPU  altogether | 策略必须能综合成电路 |

口条：**旁路解决「软件收发包太慢」；FPGA 解决「连解析和簿记都要确定延迟」。** 中频股票两条都可以不上。

## 几个必须会的词（别展开成 EE 课）

- **流水线 / 吞吐 vs 延迟**：加深流水能提频，但单笔不一定更快；交易更在乎单笔 tick-to-trade。
- **组合逻辑 vs 寄存器**：太深的组合路径会降时钟；拆拍会加延迟。
- **时钟域**：行情收、PCIe、主机 TSC 不是同一钟。跨域要异步 FIFO，别拿主机 `now()` 减板上时间当延迟。
- **HLS vs Verilog**：HLS（C++ 综合）迭代快、面积/时序难控；关键路径仍常手写 RTL。没写过就说「我理解分工，没交过时序收敛」。
- **PCIe / DMA**：数据一进主机内存，已经比板上慢一个数量级。还想亚微秒，决策不能回主机。

## 何时不该上 FPGA

- A 股中频、日频、换手受冲击和 T+1 约束：边在研究，不在 2μs。
- 策略每周改、要 Python 研究闭环：板上改一周，研究改一小时。
- 团队没有 RTL/HLS 和板级运维：一块闲置的 exablaze/Xilinx 比没有更糟。
- 瓶颈其实是柜台、席位、风控网关：先问 hop 账，再买板。

## 诚实说法（推荐）

> 我没交付过 FPGA 比特流。量化里我把它当延迟预算上的一跳：固定协议和硬风控可以下板，alpha 和组合留 CPU。中频股票我不会提议上板；期货热路径会先问现在是旁路还是已经 tick-to-trade，再决定架构师该补的是 C++ 热路径还是和硬件的接口。

被追问「硬件机器学习」：线速上能跑的是很小的模型（固定点、浅树、线性）。深度学习推理通常在研究集群或盘后，不是 tick 路径。
