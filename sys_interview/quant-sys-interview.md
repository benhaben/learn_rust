# 量化系统面试题集（C++ / Linux / FPGA）

可跑代码在 [`sys_interview/`](README.md)。FPGA 没有板子，口条和切分见 [`fpga.md`](fpga.md)。

先分清战场：华钧 2016 起做期货低延迟，2019 起做中频股票。同一套「架构师」要会两边说话——**中频吃数据语义和回测/实盘对齐，低频到中频的股票不必上 FPGA；期货热路径才谈绑核、旁路、FPGA。**

## 必考

| 主题 | 一句话 | 典型问法 |
|---|---|---|
| 热路径禁令 | 行情回调里禁止：heap 分配、锁、日志、异常、虚调用、syscall | 一笔 tick 里你绝不会做什么 |
| 延迟账 | 先画 hop：网卡→解析→书→策略→风控→编码→发出 | 端到端 8μs 都耗在哪 |
| 缓存行 | 64B；两线程写相邻 `atomic` 会伪共享 | 计数器变慢怎么查 |
| SPSC 环 | 单产单消无锁队列是交易系统的默认管道 | 为什么不用 `mutex+queue` |
| 内存序 | 先写 payload，再 Release；对面 Acquire 后再读 | flag 用 Relaxed 会怎样 |
| 打包结构 | 交易所二进制用 `#pragma pack` / `offsetof` 对字段，别信编译器对齐 | 解析慢在拷贝还是分支 |
| 绑核 / 隔离 | 热线程钉死一核，`isolcpus`+关超线程，旁路软中断 | 忙等为啥还要绑核 |
| 时钟 | 测间隔用 TSC / `CLOCK_MONOTONIC_RAW`；墙上时钟会跳 | 延迟数字怎么测才不算谎 |
| 内核旁路 | OpenOnload / DPDK / 厂商栈：少拷一次、少进一次内核 | 和 FPGA 各解决哪一跳 |
| FPGA 切分 | 确定性解析/簿记/风控门槛上 FPGA；复杂 alpha 留 CPU | 中频股票要不要上板 |

## 进阶

| 主题 | 一句话 |
|---|---|
| 忙等 vs epoll | 热路径 spin；冷路径（人工、文件、HTTP）才 epoll |
| 大页 / `mlockall` | 禁换页；2MB/1GB 大页降 TLB miss |
| NUMA | 内存和线程同 socket；跨 NUMA 一次多 100ns 级 |
| 组播行情 | UDP multicast + 序列号缺口检测；TCP 重传会抖 |
| 忙轮询网卡 | `SO_BUSY_POLL` / Onload `EF_POLL`；代价是一颗核 100% |
| 虚函数 | 策略热路径用模板/函数指针表，不在每 tick `virtual` |
| SSO / `string_view` | tick 里不改 `std::string`；符号用 `int32` id |
| SIMD / 批处理 | 中频截面、因子矩阵用批；期货单 tick 分支比 SIMD 重要 |
| 回测=实盘接口 | 同一份 `on_md` / `send_order`；差别只在时钟和撮合 |
| 幂等下单 | cl_ord_id、重连对账、部分成交、重复回报 |

## 压轴

| 主题 | 一句话 |
|---|---|
| 尾延迟 | 看 p99/p999 和最大，不看平均；日志、GC、中断是元凶 |
| 乱序 / 丢包 | 行情源双活要选路或合并，不能两本账 |
| 时钟域 | FPGA 内部流水 vs PCIe 到主机 vs 交易所时钟，三套不能混谈 |
| 事故四步 | 止血（停策略/切通道）→ 保资金（撤未报、对账）→ 定位 → 门禁 |
| 中频 vs 高频 | 中频：冲击、T+1、撮合仿真；高频：hop 数、抖动、共址 |

## 全链路（面试默画）

```text
交易所/柜台
    │  UDP 组播 / TCP 柜台
    ▼
[NIC] ──内核协议栈──► 10–50μs
    │
    │  旁路 (Onload/DPDK) ──► 1–5μs
    │
    │  FPGA 解析+簿记     ──► 100ns–1μs 到决策沿
    ▼
共享内存 / SPSC
    ▼
策略线程（绑核、忙等）──► 风控（限额、撤单、自成交）──► 下单
    │
    └── 中频股票：同一接口进回测引擎；热路径仍禁止分配
```

## 数字卡（口条用，不是承诺）

| 一跳 | 数量级 | 备注 |
|---|---|---|
| L1 / L2 / 跨 NUMA | ~1 / 4 / 100 ns | 别在热路径跨 socket |
| 系统调用 / 上下文切换 | 0.2–2 μs / 几 μs | 热路径不要 `write` 日志 |
| 内核 TCP 收包 | 10–50 μs | 含中断、拷贝、协议 |
| 内核旁路 | 1–5 μs | 仍是软件策略 |
| FPGA tick-to-trade | 数百 ns–1 μs | 策略必须能下沉到 RTL/HLS |
| 上海/中金所共址 | 看柜台风控，不是网卡广告 | 先问柜台、再谈板卡 |

A 股中频（秒到分钟）：FPGA 几乎不改 PnL；先做 PIT、成本、成交滞后。  
期货做市/抢价：每一跳都要能说清。

## 热路径 C++ 口条

- 对象模型：热数据 SoA 或紧凑 POD；冷字段（名字、备注）拉开。
- 所有权：热路径 `unique_ptr` 都嫌重，预分配对象池；`shared_ptr` 原子计数是抖动。
- 异常：交易进程启动期可以抛；tick 里 `noexcept`，错误走状态机。
- 内存序：x86 上错误代码常「能跑」，ARM/面试会拆。口条与 `30_atomic_order` 相同：先写数据，再 Release。
- 和 Rust 对照：`unique_ptr`≈`Box`，`shared_ptr`≈`Arc`；C++ 不会在编译期拦住数据竞争。

## Linux 口条

- 绑核：策略线程、行情线程、隔离核；把 irq 赶到别的核。
- 隔离：`isolcpus`、`nohz_full`、关 SMT，减少被踢出 cache。
- 锁页：`mlockall(MCL_CURRENT|MCL_FUTURE)`，禁 swap。
- 测时：校准 TSC；跨核比 TSC 前先确认恒定 TSC。
- 旁路：能讲「少一次内核拷贝、少一次中断」即可；没做过就别编 Onload API。

## FPGA 口条（没做过板也能说）

见 [`fpga.md`](fpga.md)。三句就够：

1. FPGA 买的是**确定延迟**和**线速解析**，不是「算得比 CPU 聪明」。
2. 适合：二进制行情解码、订单簿增量、简单触发、硬风控门槛、订单编码。
3. 不适合：经常改的 alpha、树模型、组合优化、研究迭代。中频股票优先 CPU。

没交过板：说「我没交付过 FPGA，但知道它切在哪一跳、和旁路/CPU 怎么分工」。装过会比不会更致命。

## 事故四步（压力面）

1. **止血**：停自动下单 / 切备用行情 / 冻结出站。
2. **保资金**：未报撤、持仓对账、防止重复单。
3. **定位**：同一套时间戳（TSC 或交易所），看是网、解析、策略还是柜台。
4. **门禁**：重放、延迟回归、双账检测；没门禁不准回自动。
